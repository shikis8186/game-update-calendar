# ゲーム更新カレンダー

各ゲームのアップデート・メンテナンス・事前ダウンロードの予定を自動で集め、Web ページのカレンダーにまとめます。
GitHub Actions で定期的に情報を集め、GitHub Pages で公開します（無料・URL を知っていれば誰でも閲覧可）。

- PC ではカレンダー表示、スマホ（画面幅 600px 未満）では一覧表示に自動で切り替わります（ボタンで手動切り替えも可）
- 「DLありのみ」で、ダウンロードが発生する予定だけに絞れます
- 予定を押すと、ダウンロードの有無・サイズ・**判定根拠**・**公式の情報源へのリンク**が表示されます

## 精度についての考え方

推測で「ダウンロードあり」とは表示しません。各予定には次の 3 つの状態があります。

| 表示 | 意味 |
|---|---|
| **確定**（塗りつぶし） | 実際の配信データ、または公式告知の「実施済み」の記載で確認できたもの |
| **予定**（枠線） | 公式告知にもとづく今後の予定 |
| **見込み**（枠線） | 告知の種類から推定したもの。配信が確認できた時点で自動的に「確定」に変わる |

- Steam のゲームは、ビルド更新を監視している期間内で、告知の前後 24 時間にビルド更新がなければ「ダウンロードなし」と確定します。
  監視を始める前の告知は、確定できないため「見込み」のまま表示します（運用を続けるほど確定できる範囲が広がります）。
- 情報源の取得に失敗した場合は、誤ったデータを出さず、前回のデータを残して「取得失敗」と表示します。
- 時刻はすべて日本時間です。LoL のみ、Riot 公式の予定日（米国太平洋時間の日付）です。

## 公開までの手順（最初の 1 回だけ）

1. **GitHub アカウント**を用意します（https://github.com/ で無料登録）。
2. **新しいリポジトリ**を作ります（右上の「＋」→「New repository」）。
   - 名前は自由（例: `game-update-calendar`）
   - **Public**（公開）を選びます（無料プランで GitHub Pages を使うため）
3. このフォルダの中身をリポジトリにアップロードします（下の「アップロード方法」参照）。
4. リポジトリの **Settings → Pages** を開き、「Build and deployment」の **Source** を **GitHub Actions** にします。
5. **Actions** タブ →「カレンダーの更新」→「Run workflow」で初回の実行をします。
6. 数分後、Actions の実行結果に表示される URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）でカレンダーが見られます。

以降は 3 時間ごとに自動で情報を集め、ページを更新します。

### アップロード方法（git を使う場合）

```bash
cd game-update-calendar
git init -b main
git add .
git commit -m "ゲーム更新カレンダーを追加"
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git push -u origin main
```

初回の `git push` で GitHub へのログイン画面が開くので、ご自身でログインしてください。

## よくある変更

### ゲームを追加・削除する
`config/games.toml` を編集します。書き方はファイル先頭の説明を参照してください。
Steam で配信されているゲームなら、Steam のアプリ ID（ストアページの URL `store.steampowered.com/app/<この数字>/`）を書くだけで追加できます。

### 更新の頻度を変える
`.github/workflows/update.yml` の `cron` を変更します（時刻は UTC）。
- 3 時間ごと（初期設定）: `17 */3 * * *`
- 1 日 1 回（日本時間 6:17）: `17 21 * * *`

### 手元で動かす（確認用）

```bash
python -m unittest discover -s tests -t .
python -m collector
python -m http.server 8765 --directory docs
```

ブラウザで http://localhost:8765/ を開くと確認できます（Python 3.11 以上。追加のインストールは不要です）。

## フォルダ構成

| 場所 | 内容 |
|---|---|
| `config/games.toml` | 対象ゲームと色・情報源の設定 |
| `collector/` | 情報を集めて判定するプログラム（Python・標準ライブラリのみ） |
| `tests/` | 判定ロジックの自動テスト（実際の告知文の書式で確認） |
| `docs/` | 公開される Web ページ（`docs/data/events.json` が予定のデータ） |
| `state/state.json` | ビルド番号やバージョンの検知履歴（確定判定に使う） |
| `.github/workflows/update.yml` | 定期実行と公開の設定 |

## 注意事項

- 各情報源には、公式サイトや公式 API が一般向けに公開している情報を、1 回の実行につき数十回程度の頻度で取得しています。
- 情報源となるサイトの仕様が変わると、そのゲームだけ「取得失敗」になることがあります。その場合はページ下部の「データの取得状況」に表示されます。
- 掲載している情報の正確さは各公式の発表に依存します。重要な判断の前には、詳細欄のリンクから公式の告知を確認してください。
